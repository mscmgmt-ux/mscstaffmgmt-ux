## 2. 赤の扱い ★最重要

**参考画像の深い赤をそのまま文字色にすると、黒背景で 4.10:1 となり AA(4.5:1) を満たさない。**
用途で2本立てにした。

| トークン | 値 | 用途 | 実測 |
|---|---|---|---|
| `--red-ink` | `#FF3B45` | 枠線・文字・アイコン・グロー | 背景上 **5.68:1** OK |
| `--red-fill` | `#E1121D` | 塗りボタン（白文字を載せる） | 白文字で **4.88:1** OK |

**明るい赤 `#FF3B45` を塗りにして白文字を載せると 3.52:1 で不足する。** 塗りは必ず深い赤を使う。

参考画像の主役は輪郭ボタンなので、実際には `--red-ink` の出番が多い。

### 状態色は赤と別系統にした

赤をブランドのアクセントに使うため、**「エラー = 赤」と衝突しないよう状態色を別に確保**した。

| 用途 | 値 | 実測 |
|---|---|---|
| 確定・回答済み | `#3ED67F` | 10.61:1 |
| 未回答・要確認 | `#FFB020` | 10.94:1 |
| エラー・不足 | `#FF5A63`（アクセントより明るい赤） | 6.57:1 |

## 3. 仕様書に合わせて変えたところ ★重要

### 3-1. 日程選択を2値 → 3状態にした

**参考画像の日程選択は「参加する / しない」の2値**（チェックが付くかどうか）。
しかし仕様書は **参加可能 / 要請があれば参加可能 / 参加不可** の3状態を要求している。

そのため、日ごとの列に3つの選択肢を縦に積み、その下に宿泊を置いた。

**「参加不可」を選んだときだけ赤くしない。** 赤 = 参加できる日、という意味づけを崩さないため、
無彩色 + ✕ のままにしている。

### 3-1b. 日程グリッドを横スクロールにし、未回答ガードを入れた（2026-08-01 追記）

開催日は**最大13日**（オーナー確認済み。ただしほぼ社員で、外注は分割）。
縦に伸ばさず横スクロールで見せる方針を採用した。

**13日での実測（2026-08-01）**

| 項目 | 5日 | 13日 |
|---|---|---|
| 横スクロール量 | 552px | 1,448px（約4.7画面分） |
| グリッドの高さ | 275px | **275px（変わらず）** |
| ページ全体の高さ | 1,220px | **1,220px（変わらず）** |

日数が増えても縦には伸びず、他セクションの位置が動かない。**縦並びへの切り替えは不要と判断した。**

**ただし横スクロールは「隠れている日に気づかない」事故が起きやすい。**
仕様書上、回答は提出後にスタッフ自身で変更できないため、見落としの代償が大きい。
三重に手当てしている。

1. **列幅を 104px に固定**し、3列目が必ず途中で切れる（端でぴったり切らない）。右端にフェード
2. **「回答済み 3/13日　未回答が2日あります」のカウンタとバー。** 隠れた日の存在を数で示す。
   未回答の日は破線の枠と「未回答」の文字でも示す
3. **未回答が残る間は「次へ」で進めない。** 押すと最初の未回答日へ自動スクロールしてフォーカス

**実装上の注意**: 「次へ」を `disabled` にすると click が発火せず、3 の案内が出せない。
`aria-disabled` + クラスで見た目だけ落とし、押せる状態は保っている。

宿泊は、**参加不可の日と最終日**で自動的に無効になる。

### 3-2. 宿泊を「日ごと」にした

design-1 では宿泊を全体で1回聞いていたが、参考画像は日ごとに宿泊トグルを持つ。
**仕様書の「宿泊」タブは宿泊日を持つ**ので、日ごとのほうがデータ構造に忠実である。
喫煙区分と部屋タイプは日をまたいで共通なので、別セクションにまとめた。

参加不可の日は宿泊を選べないようにしている（JS で `disabled`）。

### 3-3. ホーム画面を追加した

design-1 は4桁コードから直接1イベントの回答に入る流れだった。
参考画像はホームでイベントを並べる構成で、**仕様書の「年間イベント登録」に忠実**なので採用した。
状態チップは仕様書の語彙に合わせた（未回答 / 参加確定 / 受付前 / 見送り）。

### 3-4. 参考画像から外したもの

- **メッセージ機能とそのタブ。** 仕様書は「返信は確認しない旨を本文に記載」としており、
  アプリ内メッセージは存在しない。代わりに「事務局」タブを置いた
- **サムネイル画像。** スタッフ・イベントに相当する画像が無いため、
  頭文字のタイルで代替し、行の左端の目印だけ残した

### 3-5. 名称は仮

`MSC EventOps` は、当時の仮アドレス案から置いたもの。
Gmail アドレスは `noreply.msc.mgmt@gmail.com` に確定した（2026-08-01）が、
ワードマーク自体は語呂合わせであり、**正式名称は未決定。** ロゴの線画は自前で描いたもので、参考画像の複製ではない。

## 4. 事務局管理画面

**参考画像に対応する画面が無い。** 配色・チップ・ボタンなど部品だけ引き継ぎ、
レイアウトは業務画面として組んだ（`body class="dense"`、グローは使わない）。

design-1 で見つかった「必要室数の白線が右端で見えにくい」問題を作り直した。
**不足分を斜線で塗る**方式にしたので、色が見えない環境でも不足が分かる。

## 6. ブラウザで確認したこと / していないこと

**確認した（2026-08-01、375×812 と デスクトップ幅）**
- 5画面の表示
- 日程グリッドの3状態選択と、参加不可の日・最終日の宿泊が無効になること
- ステップ 2 → 3 の遷移とステップインジケータの変化
- 管理画面の数値タイル・室数照合・表の横スクロール
- **日程グリッドの横スクロール。13日に増やしたときの実測（§3-1b）**
- **未回答カウンタの更新と、全日回答時に「次へ」が解放されること**

**確認していない**
- hover / focus の実際の見え方
- 実機の iOS / Android での表示。**特にグローの見え方は端末差が出やすい**
- **実機での横スクロール操作。縦スクロールとの競合（斜めスワイプ時にどちらが優先されるか）は
  実機でないと分からない。** `overscroll-behavior-x: contain` は入れてある
- スクリーンリーダーでの読み上げ。カウンタの `aria-live` が実際に読まれるかは未確認
- **プレビューペインがリロードを受け付けない状態になったため、`answer.html` の初期表示は
  画面内のボタン経由でしか確認していない**（HTML の初期状態は日程選択が開く指定）

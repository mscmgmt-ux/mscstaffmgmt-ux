# Phase 0 セットアップ手順（人間が行う作業）

作成日: 2026-08-01 ／ 対象: MSC イベント運営システム

**この作業はすべて人間が行います。** Claude は Google アカウントの作成・ログイン・
デプロイ・`git push` を代行しません。

**上から順に実施してください。** 後半の手順は前半の結果に依存します。

---

## ★ 最初に: Claude に伝えてよいもの / 絶対に伝えないもの

| 種別 | 扱い |
|---|---|

| **スプレッドシートの ID / URL** | **絶対に伝えない・コミットしない** |
| **管理者の許可メールアドレス一覧** | **絶対に伝えない・コミットしない** |

## E. clasp を導入する

| # | 作業 | コマンド |
|---|---|---|
| E-1 | Node.js のバージョンを確認（**20.0.0 以降が必要**） | `node -v` |
| E-2 | clasp をインストール | `npm install @google/clasp -g` |
| E-3 | ログイン（**ブラウザで A のアカウントを選ぶ**） | `clasp login` |
| E-4 | `gas/` に GAS プロジェクトを紐づける | `cd gas && clasp clone <スクリプトID>` |
| E-5 | `.clasp.json` と `.clasprc.json` が git に載っていないことを確認 | `git status` |

E-5 は重要です。`.gitignore` に入れてありますが、目視で確認してください。

**反映は3段です。`clasp push` だけでは公開中のアプリは変わりません。**

```
clasp push      → ソースを Drive へアップロード（まだ利用者には反映されない）
clasp version   → バージョンを作る
clasp deploy    → デプロイを更新して初めて反映される
```

## F. デプロイを2本作る

スタッフ用と管理者用で公開設定が異なります（決定事項）。

| | スタッフ用 | 管理者用 |
|---|---|---|
| 次のユーザーとして実行 | **自分（オーナー）** | **ウェブアプリケーションにアクセスしているユーザー** |
| アクセスできるユーザー | **全員（匿名ユーザーを含む）** | **Google アカウントを持つ全員** |

**★ 管理者用デプロイの重要な注意**

「Google アカウントを持つ全員」は**管理者限定ではありません。** URL を知っている
すべての Google ユーザーが呼べます。**許可メールリストの照合を実装するまで、
管理者用デプロイに機密データを扱う処理を載せないでください。**

Phase 0 の時点では、管理者用は「ログインしたユーザーのメールアドレスを返すだけ」の
確認用コードに留めます。

## G. 疎通確認（★ここが Phase 0 の合否）

**この2つが通らないと、構成が根本から成立しません。**

### G-1. CORS 疎通

| # | 作業 |
|---|---|
| G-1-1 | Claude が用意する確認用コード（GAS 側 + HTML 1枚）を配置する |
| G-1-2 | GAS をデプロイし、GitHub Pages の URL からブラウザで開く |
| G-1-3 | 画面に GAS が返した固定の文字列が出るか確認 |
| G-1-4 | 出ない場合、**ブラウザの開発者ツール → Console と Network** の内容を Claude に伝える |

**想定している回避策**: `POST` + `Content-Type: text/plain` + カスタムヘッダなし。
GAS の Web App は `doGet` / `doPost` にしか応答せず、OPTIONS を処理できないため、
プリフライトが発生しない条件に寄せます。**これは未検証です。**

通らなければフロントから API を一切叩けません。その場合は構成の見直しになります。

### G-2. `Session.getActiveUser().getEmail()` の確認

| # | 作業 |
|---|---|
| G-2-1 | 管理者用デプロイにアクセスし、自分のメールアドレスが返るか確認 |
| G-2-2 | 返らない場合（空文字など）、その結果を Claude に伝える |

返らなければ管理者認証の方式を作り直します。

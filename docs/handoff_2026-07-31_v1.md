## 2. STEP 0 で決まった事項と、その理由

| 決定 | 理由 |
|---|---|
| 督促メールは**日跨ぎで分割送信**する | 無料 Gmail の上限は **100 宛先/日**（Apps Script 公式クォータ）。スタッフ30〜50名・単一イベントなら収まるが、100名または複数イベントの締切が近接すると超過する |
| **デプロイを2本**に分ける（スタッフ用 `ANYONE_ANONYMOUS`+`USER_DEPLOYING` / 管理者用 `ANYONE`+`USER_ACCESSING`） | `USER_ACCESSING` なら実行ユーザー＝アクセスユーザーになり、メールアドレスが確実に取れると見込んだため。`USER_DEPLOYING` で取れるかは公式ドキュメントで確認できなかった |
| 4桁コードの**個人単位ロックアウトを作らない**。遅延1〜2秒＋全体レート制限にする | GAS の `e` オブジェクトに IP・User-Agent が無く、個人単位の厳密な識別ができない。端末IDは localStorage で偽装可能。また4桁の先に「氏名+登録メール一致」の2段目がある |
| **回答行を回答依頼の時点で事前生成する**（仕様書に無い設計追加。承認済み） | 行の追記ではなく既存行の更新になり、1行を書く人が常に1人になる。**行追記の競合が構造的に消え、LockService が不要になる** |
| `LockService` は**版番号の採番だけ**に使う（`getScriptLock` + `tryLock`、自動再試行なし） | 単調増加の採番だけは競合すると実害が出る。実行6分上限があるため長い `waitLock` は使わない |
| バックアップは**平常時 月次 CSV / 回答受付期間中 日次 CSV + 版履歴** | 週次だと回答集中期に最大1週間分を失う。GitHub はコードしか守らず、データ（スプレッドシート）は別途必要 |
| テストは**計算ロジックのみ Node.js で**。画面とメールは人間確認 | GAS のサービスは Google 上にしか存在せず、ローカル・コンテナで再現する公式手段がない。一方、必要室数や差分は純粋計算なので手元で検証できる |
| リポジトリは **public** | 無料プランでは Pages が public リポジトリでしか公開できない。private にしても公開サイト自体は誰でも見られるため、GAS URL の秘匿には繋がらない |
| **clasp を使う** | 使わないと GAS のコードがブラウザ内にしか存在せず履歴が残らない。開発者不在運用で「今動いているコードがどれか分からない」状態になる |
| ロゴ画像を使う可能性があるため `assets/` を作り**最初から git 管理**する | 途中で方針を変えると追跡済みと未追跡が混在して事故る |
| 開発段階では**ブランチを切らず `main` に直接コミット**する | オーナーの判断 |
| ドキュメント更新は**デプロイを伴う変更のとき** | コミット毎は破綻する（チェックリスト 1-8） |
| GitHub Pages の公開元を**リポジトリルート**にする | 無料プランの選択肢は `main/(root)` か `main/docs` のみ。`docs/` はドキュメントに使う。Actions を使えば任意だが、開発者不在運用で依存を増やしたくない |

## 6. 引き継ぐ人への注意

- **このリポジトリは public である。** コミットしたものは全世界から読める（`CLAUDE.md` §2-1）
- **GAS は `git push` では反映されない。** `clasp push` → `clasp version` → `clasp deploy` の3段が必要
- **管理画面は許可メール照合を実装するまで全 Google ユーザーに開いている。** 照合なしで公開しない
- **`localhost` / `127.0.0.1` への接続は macOS の OS 層で拒否される。** 画面確認は人間かブラウザツールで行う
- 実装が正、ドキュメントは参考。食い違ったらコードを信じる（`CLAUDE.md` §7）

# フェーズ計画 v1

作成日: 2026-07-31 / 対象: MSC イベント運営システム

仕様書「確定構成 v1」の業務フロー（年間イベント登録 → 回答依頼 → スタッフ回答 → 締切 →
参加者決定 → 確定リスト公開 → 宿泊確定 → ホテル名簿出力 → 差分管理）を実装順に落としたもの。

**各フェーズは別プロンプトで依頼する。** このファイルは順序と依存関係の記録である。

---

## Phase 0: 実環境の疎通確認（人間の作業が主）

構成が成立するかを、コードを書く前に確かめる。**ここが通らないと以降が全部無駄になる。**

| 何を | 誰がどう検証するか | 依存 |
|---|---|---|
| `noreply.msc.mgmt@gmail.com` を作成し、2段階認証・復旧手段を設定 | **人間**（Claude はアカウント作成をしない） | — |
| GitHub に public リポジトリを作成し Pages を有効化（公開元 = `main` / `(root)`） | **人間**（`git push` はオーナー確認後） | — |
| clasp を導入（Node.js 20+、`npm install @google/clasp -g`、`clasp login`） | **人間**（Google ログインが必要） | Gmail アカウント |
| 空の HTML 1枚から GAS が返す固定 JSON を取得できるか（**CORS 疎通**） | **人間**が公開 URL で確認。Claude は結果を受け取るのみ | 上記すべて |
| `Session.getActiveUser().getEmail()` が管理者用デプロイで値を返すか | **人間**が実環境で確認 | GAS デプロイ |

**この2つが Phase 0 の合否である。** 落ちた場合は構成の作り直しになる。

- CORS: `POST` + `Content-Type: text/plain` + カスタムヘッダなし でプリフライトを回避する想定。
  **未検証。** 動かなければフロントから API を一切叩けない
- `getActiveUser()`: 値が返らなければ管理者認証の方式を作り直す

## Phase 1: スタッフ認証と回答受付

| 項目 | 内容 |
|---|---|
| **作るもの** | スプレッドシートの全タブ作成／4桁コード判定（遅延1〜2秒＋全体レート制限）／氏名選択・メール一致確認／回答画面／**回答行の事前生成** |
| **検証** | 認証ロジックの分岐は **Claude が Node.js テスト**。画面表示は **Claude がブラウザで確認（実行可否は未検証）**。実際の回答送信は **人間**が実環境で |
| **依存** | Phase 0 の CORS 疎通が通っていること |

回答行は回答依頼の時点で「イベント × 開催日 × スタッフ」を全て「未回答」で生成する。
これにより行追記の競合が構造的に発生せず、LockService が不要になる（設計上の確定事項）。

## Phase 2: 事務局の参加者決定と確定リスト公開

| 項目 | 内容 |
|---|---|
| **作るもの** | 管理者用デプロイ（`ANYONE` + `USER_ACCESSING`）／**許可メール照合**／未回答者一覧／参加決定・見送り・取消／「事務局編集中」「公開済み」の切替／確定リスト表示画面 |
| **検証** | 集計・抽出ロジックは **Claude が Node.js テスト**。管理画面の権限は **人間**が別アカウントでアクセスして確認 |
| **依存** | Phase 1 の回答データ／Phase 0 の `getActiveUser()` 確認 |

**許可メール照合は管理者用デプロイと同時に実装する。** 照合なしで公開しない。

## Phase 3: 督促メール

| 項目 | 内容 |
|---|---|
| **作るもの** | 未回答者の抽出／**日跨ぎ分割送信のキュー**（無料 Gmail は 100 宛先/日）／定期トリガー／メール履歴タブへの記録／送信エラー表示／管理画面からの再送 |
| **検証** | 分割ロジック（1日あたり何通に割るか）は **Claude が Node.js テスト**。**実際のメール送信と着信は人間が確認**。Claude はメールを送らない |
| **依存** | Phase 1 の回答ステータス／Phase 2 の管理画面 |

上限 100 宛先/日は**その日の全送信の合計**である。督促・回答確認・再送が同じ枠を食う。
キューは「今日あと何通送れるか」を持ち、超過分を翌日へ繰り越す。

## Phase 4: 宿泊集計とホテル提出

| 項目 | 内容 |
|---|---|
| **作るもの** | 宿泊要否・喫煙区分・部屋タイプの集計／必要室数の算出／部屋確保との突合／CSV / Excel 出力／**版番号の採番（ここだけ `getScriptLock`）**／ホテル提出・提出明細タブへの記録 |

ホテル様式の設計は本計画の範囲外。着手前に様式を確定させる必要がある。

## Claude が自力で検証できない範囲（全フェーズ共通）

- GAS の実行、スプレッドシートの読み書き、Gmail の送信 — **Google アカウントが必要**
- GitHub Pages 上での実際の動作 — **push とデプロイが必要**
- CORS 疎通 — 実際の GAS デプロイに対してのみ確認できる
- `localhost` / `127.0.0.1` への接続は macOS の OS 層で拒否される（環境の既知制約）

**上記はすべて人間が確認する。** Claude は結果を受け取って判断するのみで、
確認できていないものを「動く」と報告しない。
